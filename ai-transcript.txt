❯ what does .every take in as a parameter?

⏺ .every() takes a callback function as its parameter, plus an optional thisArg
  as a second argument. It runs the callback on each element and returns true
  only if the callback returns a truthy value for every element.

  array.every(callback, thisArg?)

  The callback gets up to three arguments:

  (element, index, array) => boolean

  - element: the current item being checked
  - index (optional): that item's position
  - array (optional): the array .every() was called on

  Examples:

  [2, 4, 6].every(n => n % 2 === 0);   // true
  [2, 3, 6].every(n => n % 2 === 0);   // false (stops at 3)

  In tic-tac-toe, it's handy for checking whether all three cells in a winning
  line belong to the same player:

  const line = [0, 1, 2];
  const isWin = line.every(i => board[i] === "X");

  Or for checking whether the board is full (a draw):

  const isFull = board.every(cell => cell !== null);

  A few other things to know:
  - It stops early. As soon as the callback returns false, .every() returns
    false without checking the remaining elements.
  - An empty array returns true. [].every(...) is always true, because no
    element fails the check.
  - The opposite is .some(), which returns true if at least one element passes.

⏺ You've already got the four cells right. There are two other things to handle.

  1. Stop the loops one short. Every square uses row+1 and col+1, so if row
  reaches the last row, board[row+1] is undefined and board[row+1][col] throws
  an error. On a 4x4 board the top-left corner of a 2x2 square can only be at
  index 0, 1, or 2, so loop to length - 1:

  for (let row = 0; row < board.length - 1; row++) {
    for (let col = 0; col < board[row].length - 1; col++) {

  2. Compare everything to the top-left cell and skip empty squares. This is the
  same approach as your checkCorners:

  private checkBoxes(board: Board): Player | null {
    for (let row = 0; row < board.length - 1; row++) {
      for (let col = 0; col < board[row].length - 1; col++) {
        const topLeft = board[row][col];
        if (!topLeft) continue; // empty cell, so this square can't be a win

        if (
          topLeft === board[row][col + 1] &&
          topLeft === board[row + 1][col] &&
          topLeft === board[row + 1][col + 1]
        ) {
          return topLeft;
        }
      }
    }
    return null;
  }

  Use continue here, not return null like in checkCorners. An empty cell only
  rules out this one square, so the loop should move on to the next one.

  If you'd like to reuse .every(), you can put the four cells in an array
  instead:

  const square = [
    board[row][col], board[row][col + 1],
    board[row + 1][col], board[row + 1][col + 1],
  ];
  if (square[0] && square.every(cell => cell === square[0])) return square[0];

  Also, your current checkBoxes has no return after the loops. TypeScript will
  report an error for that, because the function promises to return Player |
  null. The return null; at the end of the version above fixes it.

⏺ Yes, there are a few, though the speed gain will be tiny. The board only has
  16 cells, so each check is already effectively instant. The real wins are less
  repeated work and less duplicated code. None of these change what the methods
  return, so all 78 tests (still passing) would stay green.

  1. isGameOver validates the board three times. It calls validateBoard, then
  checkWinner validates again, then anyMovesLeft validates a third time. You
  could move the logic into private helpers that skip validation, and have the
  public methods validate once and then call them:

  public checkWinner(board: Board): Player | null {
    this.validateBoard(board);
    return this.findWinner(board);
  }

  public anyMovesLeft(board: Board): boolean {
    this.validateBoard(board);
    return this.hasEmptyCell(board);
  }

  public isGameOver(board: Board): boolean {
    this.validateBoard(board);
    return this.findWinner(board) !== null || !this.hasEmptyCell(board);
  }

  findWinner would hold the current horizontal → vertical → corners → diagonal →
  boxes chain, and hasEmptyCell would be board.some(row => row.includes(null)).

  2. Each line is scanned twice, once for X and once for O. You can check a line
  once by comparing every cell to the first cell, the same way checkCorners and
  checkBoxes already do. A shared helper removes the six repeated every pairs:

  private lineWinner(cells: (Player | null)[]): Player | null {
    const first = cells[0];
    return first && cells.every(cell => cell === first) ? first : null;
  }

  Then each check gets shorter, for example:

  private checkHorizontal(board: Board): Player | null {
    for (const row of board) {
      const winner = this.lineWinner(row);
      if (winner) return winner;
    }
    return null;
  }

  A line that starts with null returns null right away, which is the same result
  as now, so this doesn't add an edge case.

  3. Small cleanups:
  - Magic number: row[3 - idx] in checkDiagonal hardcodes the size.
    row[board.length - 1 - idx] says what it means. It's equivalent because the
    board is always validated as 4x4.
  - isGameOver return: if (...) return true; return false; can just be return
    condition;.

  I wouldn't change the check order. On a board where X and O both have a line,
  the order decides who gets reported as the winner. Your case 9 test only
  checks that a single winner comes back, but keeping the order means the
  behavior stays exactly the same.
